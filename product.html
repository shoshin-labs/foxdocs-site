Product

The work after you import the file.

Foxdocs is not a blank-page writer. You bring a document in, then you put it through the loop until you can stand behind it.

Import

Start with the policy you already have.

Upload the file. Analyse it if you want a first read. The register holds the original so later versions have somewhere to come from.

Overhaul

Rewrite the whole thing when the draft is not fit.

An overhaul is a tracked job. You see the run and the result beside the file you brought in.

Improvement plan

List the changes. Then run them.

Create the plan, accept or reject each proposal, then execute. Nothing lands unless you said yes.

Reviews

Come back on a cycle. Each pass is a version.

Fidelity, completeness, mechanics, style. Periodic reviews check it still complies. They do not silently edit the live file. They cut v2, v3, v4.

Publish

The signed-off version is the one people see.

Classification, branded export, timeline, activity. The published view is read-only.

Distribute

Send it to the team, not just the editors.

Employees are a separate register from app users. Acknowledgements match the org, not the seat count.
